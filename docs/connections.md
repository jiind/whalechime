# Docker 서버 연결

트레이의 **설정 → 서버 연결 설정**에서 이름·주소·감시 여부를 지정한다. 서버는 최대 100대까지 등록하며 서버 하나의 연결 실패가 나머지 서버 수집을 중단하지 않는다.

## HTTP

`http://호스트:포트`를 사용한다. TLS·CA·클라이언트 인증서는 입력하지 않는다. 통신은 평문이며 LAN이라는 사실만으로 Docker API 접근이 제한되지는 않는다. 서버에서 접근 가능한 네트워크·클라이언트를 관리한다. 앱은 Docker 원격 포트를 자동으로 열지 않는다.

## HTTPS와 mTLS

`https://호스트:포트`를 입력하면 HTTPS 설정이 나타난다.

- CA 인증서 경로를 비우면 시스템이 신뢰하는 CA를 사용한다. 사설 CA는 PEM 파일의 로컬 경로를 지정한다.
- 서버 이름과 인증서의 유효성을 항상 검증한다.
- 서버가 클라이언트 인증서를 요구하면 mTLS를 켜고 인증서·개인키 PEM 파일 경로를 지정한다.
- mTLS를 끈 HTTPS도 서버 인증서 검증을 유지한다. 클라이언트 인증과 서버 검증은 별도 설정이다.
- 파일은 앱을 실행하는 사용자 권한으로 읽을 수 있어야 한다. 개인키 원문을 웹 입력·조회 응답·로그에 복사하지 않는다.

## SSH

`ssh://사용자@호스트:포트` 또는 `ssh://SSH별칭`을 사용한다. 로컬 OpenSSH의 기존 설정·키·에이전트를 재사용하며 개인키 파일을 별도로 선택할 수도 있다.

- `BatchMode=yes`와 `StrictHostKeyChecking=yes`를 사용한다. 비밀번호나 새 호스트 확인 창을 띄우지 않는다.
- 신규 서버는 사용자가 별도로 호스트 키를 확인하고 `known_hosts`에 등록해야 한다. 앱이 신뢰 목록을 자동 변경하지 않는다.
- 원격에서는 고정된 `docker system dial-stdio`로 Docker API를 운반한다. 임의 사용자 셸 명령은 받지 않는다.
- 원격 사용자에게 Docker 소켓 접근 권한이 있어야 하며 원격 Docker CLI가 필요하다.

## 수정·삭제

연결은 서버가 오프라인이어도 저장할 수 있다. **연결 확인**으로 실제 Docker 응답을 검사한다. 연결 수정·감시 해제·삭제는 해당 연결의 기존 이벤트·로그 스트림을 닫으며 Docker의 컨테이너를 변경하지 않는다.

앱의 전송 계층은 버전 협상·목록·이벤트·로그 조회만 허용한다. 이는 서버의 권한 제한을 대신하지 않는다. [Docker 보안 문서](https://docs.docker.com/engine/security/protect-access/)
