# Whalechime 제품 요구사항

이 문서는 대화에서 합의한 제품 동작을 기록한다. 아래 항목은 구현 완료 상태를 뜻하지 않는다.

현재 구현과 요구사항별 확인 결과는 [검증 기록](verification.md)을 참고한다.

## 서비스 범위

- Docker가 제공하는 변경 이벤트를 최대한 수집하고 관련 사용자에게 알린다. 이미지 pull·push와 컨테이너 상태 변경을 포함한다.
- 이미지와 컨테이너를 생성·배포·시작·중지·재시작·삭제하는 제어 기능은 제공하지 않는다.
- 변경 이벤트 이력과 Docker에서 조회 가능한 컨테이너의 stdout·stderr 로그를 읽기 전용으로 볼 수 있게 한다.
- Docker 이벤트 스트림과 컨테이너 실행 로그는 서로 다른 데이터다. 이미지 자체에는 컨테이너 실행 로그가 없다.

## 서버 구성과 개인 설정

- Go 기반 중앙 서버와 수집 에이전트를 사용하고 중앙 저장소는 PostgreSQL을 사용한다.
- Docker 서버마다 에이전트를 실행하며 여러 에이전트가 하나의 중앙 서버로 이벤트를 보낸다.
- 에이전트는 기존 Docker 접근 권한이 있는 실행 계정과 소켓 연결 설정을 사용한다. 호스트의 사용자·그룹·소켓 권한이나 시스템 서비스 설정을 자동 변경하지 않는다.
- Docker 데몬의 호스트 원본 로그는 기본 조회 범위에서 제외한다. Docker 이벤트와 Docker가 보관하는 컨테이너 로그는 기존 Docker 연결로 조회한다.
- 관리자는 서버와 관련 사용자·팀의 연결을 관리한다.
- 사용자는 자신이 받을 이벤트 항목을 직접 켜고 끈다. 개인 수신 설정으로 수집 범위를 줄이지 않는다.
- 사용자는 자신의 수신처를 직접 등록·변경·삭제하고 활성화 여부를 설정한다.
- 수신 항목과 수신처는 독립적이다. 선택한 이벤트는 사용자가 활성화한 모든 수신처로 발송하며 이벤트별로 채널을 지정하지 않는다.
- 알림 채널은 메일·Slack·Teams에 한정하지 않고 연동 가능한 서비스를 추가할 수 있게 한다.
- 중앙 서버가 사용자 설정과 발송 상태를 관리한다. PC의 트레이 앱을 종료해도 중앙의 이벤트 수집과 외부 알림 발송은 계속된다.

## 트레이와 설정 화면

- 사용자 PC에서 트레이 아이콘을 우클릭하면 메뉴 목록을 표시한다. 우클릭만으로 웹 페이지를 열지 않는다.
- 트레이 메뉴에는 `웹으로 이동` 항목과 접근 가능한 Docker 서버 목록을 별도로 제공한다.
- `웹으로 이동`은 중앙 웹의 일반 진입 화면을 연다. 웹의 기본 화면을 로그 전용 화면으로 정하지 않는다.
- Docker 서버 항목을 펼치면 해당 서버의 컨테이너 목록을 옆으로 펼쳐지는 하위 메뉴로 표시한다. 서버·컨테이너 선택 과정은 모두 트레이 메뉴 안에서 이루어진다.
- 하위 메뉴에서 특정 컨테이너를 클릭할 때 해당 컨테이너의 로그 전용 화면을 연다. 서버 메뉴를 펼치는 단계에서는 웹이나 별도 화면으로 이동하지 않는다.
- 로그 진입 경로는 `트레이 아이콘 우클릭 → Docker 서버 하위 메뉴 펼치기 → 컨테이너 클릭 → 해당 컨테이너 로그 화면`이다.
- 사용자가 설정 메뉴를 선택하면 중앙 서버의 해당 웹 설정 페이지를 연다.
- 개인 수신 항목과 수신처 등 설정의 관리 주체는 중앙 웹이며 데스크톱에 별도 설정 화면을 중복 구현하지 않는다.
- Docklattice와 Glancelet을 참고하고 Tailscale처럼 트레이 메뉴를 웹 화면의 진입점으로 활용한다.

## 로그 전용 보기

- 트레이의 서버 하위 메뉴에서 컨테이너를 클릭하면 해당 컨테이너의 로그 전용 화면을 열고 즉시 로그를 보여준다. 열린 화면 내부에서 다시 서버·컨테이너를 선택하거나 메뉴를 찾거나 옵션을 선택하거나 조회·재생 버튼을 조작할 필요가 없어야 한다.
- 로그 전용 화면의 표시 수단은 웹 또는 위젯 창으로 구성할 수 있다. 어느 수단을 사용하든 `웹으로 이동`과는 별도의 진입 동작을 유지한다.
- 로그는 해당 웹 또는 위젯 창 내부의 전체 표시 영역을 사용한다. 작은 대시보드 카드나 별도 메뉴 안의 부가 화면으로 배치하지 않는다.
- 여기서 전체 화면은 표시 수단 내부의 전체 영역을 의미한다. 브라우저나 운영체제의 전용 전체 화면 모드로 강제 전환하는 요구가 아니다.
- 기본 범위의 최근 로그를 자동으로 불러오고 새 로그를 실시간으로 이어서 표시한다. 처음 표시하기 위해 사용자가 로그 옵션을 설정할 필요가 없어야 한다.
- 로그 화면에는 선택한 서버명·컨테이너명과 각 로그의 발생 시각을 표시해 출처를 구분할 수 있게 한다. 기본 조회 대상은 트레이에서 선택한 특정 컨테이너다.
- 로그 범위는 사용자가 접근할 수 있는 서버·컨테이너로 제한한다. 연결 실패, 로그 없음, 조회 불가능 상태를 빈 화면과 구분해 표시한다.
- 로그 화면에서 이미지나 컨테이너의 상태를 변경하는 조작을 제공하지 않는다.
